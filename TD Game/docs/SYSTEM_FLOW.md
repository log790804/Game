# 系統流程規劃

## 遊戲主流程

```text
啟動遊戲
  -> 載入素材
  -> 主選單
  -> 選擇關卡
  -> 選擇難度
  -> 進入戰鬥
  -> 整備 / 建塔 / 升級
  -> 開始波次
  -> 敵人進攻
  -> 勝利或失敗判定
  -> 結算獎勵
  -> 更新存檔、成就、科技點
```

## 戰鬥流程

```text
初始化關卡
  -> 載入地圖與敵人波次
  -> 套用難度倍率
  -> 套用科技樹加成
  -> 玩家建造塔
  -> WaveSystem 生成敵人
  -> EnemySystem 移動敵人
  -> TowerSystem 搜尋目標
  -> CombatSystem 計算傷害與效果
  -> SkillSystem 處理主動技能
  -> TowerComboSystem 檢查組合效果
  -> AchievementSystem 檢查成就條件
  -> 結算勝敗
```

## 存檔流程

```text
玩家完成關卡或變更設定
  -> SaveSystem 收集可序列化資料
  -> 寫入 localStorage
  -> 下次啟動時讀取
  -> 若資料版本不同，執行 migration
```

## 每日挑戰流程

```text
取得目前日期
  -> 產生 daily seed
  -> 依 seed 決定地圖、難度、限制條件
  -> 玩家完成挑戰
  -> 記錄完成日期與獎勵
```

## 組合塔檢查流程

```text
建塔、升級、販售或移動塔後
  -> 取得目前場上塔列表
  -> 檢查鄰近條件
  -> 檢查數量條件
  -> 檢查陣型條件
  -> 檢查科技樹解鎖條件
  -> 套用或移除組合效果
```

## UI 與 Phaser 分工

| 區域 | 負責 |
|---|---|
| 地圖、敵人、塔、子彈、特效 | Phaser |
| 主選單、關卡選擇、HUD、技能列 | Vue |
| 成就、科技樹、設定、每日挑戰 | Vue |
| 戰鬥狀態資料 | game state |
| 畫面動畫與碰撞 | Phaser systems |

原則：遊戲狀態不要完全綁死在 Phaser 物件上，重要資料要能序列化，方便存檔、除錯與測試。
